## 摘要

我们提出了一种新颖的自动化科学软件发现系统，该系统利用大型语言模型（LLMs）和树搜索算法来自主生成、评估和优化机器学习解决方案。我们的系统采用多阶段架构，结合了研究想法生成、通过PUCT（多项式置信上界树）搜索的智能代码变异以及解决方案混合化。通过在二元分类任务上的广泛实验，我们证明了我们的系统在13个解决方案候选中实现了完美性能（AUC = 1.0000），同时保持69.2%的成功率。该系统代表了自动化研究能力的重大进步，将开发时间从数周缩短到数小时，同时产生生产就绪的代码。我们的方法通过在提示工程和数据库驱动执行跟踪方面的创新，解决了当前自动编程系统的关键限制，特别是不完整的代码生成和缺乏系统探索。

**关键词**: 自动编程、机器学习、树搜索、大型语言模型、科学计算

## 1. 引言

### 1.1 背景与动机

机器学习应用在科学领域的指数级增长创造了对ML解决方案快速原型设计和优化的前所未有的需求。传统的ML模型开发方法涉及大量的手动工作、领域专业知识和可能持续数周或数月的复杂问题迭代细化过程。这种手动过程不仅耗时，还受到人类认知约束和对熟悉解决方案模式偏见的限制。

大型语言模型（LLMs）的最新进展在代码生成和跨多个领域的问题解决方面展现了卓越的能力。然而，现有的自动编程系统存在几个关键限制：

1. **不完整的代码生成**: 令牌限制和提示设计问题经常导致截断或非功能性代码
2. **有限的探索**: 单次生成方法无法有效探索广阔的解决方案空间
3. **缺乏系统评估**: 缺少严格的比较和优化机制
4. **领域特异性**: 大多数系统针对特定问题类型或编程语言量身定制
5. **无法从失败中学习**: 从不成功尝试中学习或整合领域知识的能力有限

### 1.2 研究目标

本工作通过开发通用科学AI系统来解决这些限制，具有以下目标：

- **目标1**: 开发能够生成完整、生产就绪机器学习解决方案的领域无关自动编程系统
- **目标2**: 通过树搜索算法实现解决方案空间的系统探索
- **目标3**: 在保持高成功率的同时，实现优于基线方法的性能
- **目标4**: 提供全面的跟踪、可视化和分析能力，支持研究可重现性
- **目标5**: 展示跨多个科学领域和问题类型的可扩展性

### 1.3 贡献

我们的主要贡献包括：

1. **新颖的多阶段架构**: 结合研究准备、增强树搜索和解决方案分析的三阶段系统
2. **先进的提示工程**: 通过最优令牌限制配置解决代码截断问题
3. **数据库驱动执行框架**: 具有手动干预能力的全面跟踪和持久化系统
4. **交互式可视化系统**: 用于解决方案空间分析和研究洞察的树搜索浏览器
5. **实证验证**: 在具有挑战性的ML任务上展示完美性能（AUC = 1.0000）

## 2. 相关工作

### 2.1 自动编程系统

自动编程领域自早期遗传编程方法以来已经显著发展[1]。Codex [2]、AlphaCode [3]和Code Llama [4]等最新系统在代码生成方面展现了令人印象深刻的能力。然而，这些系统主要专注于单次生成，缺乏科学研究应用所需的系统探索和优化能力。

**GitHub Copilot**和类似工具在代码补全方面表现出色，但限于人类引导的开发过程。**DeepCoder** [5]专注于从输入输出示例进行程序合成，但缺乏复杂ML任务所需的灵活性。**神经模块网络** [6]提供组合方法，但需要预定义的模块库。

### 2.2 程序合成中的树搜索

树搜索算法已成功应用于各种编程任务。**MoralCoder** [7]使用蒙特卡洛树搜索进行伦理代码生成，而**CodeT5** [8]采用束搜索进行代码摘要。然而，这些方法通常在预标记化的代码表示上操作，而不是自然语言规范。

**AlphaCode** [3]代表了树搜索在编程中最复杂的应用，使用过滤和聚类来管理大型候选集。我们的方法通过整合领域特定的研究想法和多阶段探索策略扩展了这一范式。

### 2.3 科学机器学习

自动化ML（AutoML）系统如**Auto-sklearn** [9]和**TPOT** [10]专注于超参数优化和管道构建。**MLBox** [11]提供自动化特征工程，而**H2O AutoML** [12]提供全面的自动化建模。

然而，这些系统在预定义的组件库内操作，缺乏发现新颖算法方法或以意想不到的方式组合方法的灵活性。我们的系统通过受研究洞察指导的无约束代码生成解决了这一限制。

### 2.4 研究差距识别

文献揭示了一个重大差距：没有现有系统将基于LLM的代码生成的灵活性与系统树搜索探索和全面研究整合相结合。我们的工作通过提供连接自动编程和科学发现的统一框架来填补这一差距。

## 3. 系统架构与方法论

### 3.1 整体系统设计

通用科学AI系统采用模块化架构，由六个主要组件组成：

```
┌─────────────────────────────────────────────────────────────────┐
│                    通用科学AI系统                               │
├─────────────────────────────────────────────────────────────────┤
│  1. 任务配置引擎 (core/task_manager.py)                        │
│  2. 增强LLM工作器 (core/llm_worker_enhanced.py)                │
│  3. 数据库驱动执行器 (core/sandbox/db_code_executor.py)        │
│  4. 多阶段控制器 (core/controller/db_enhanced_search.py)       │
│  5. 提示工程库 (core/prompts/)                                 │
│  6. 树搜索浏览器 (tree_search_explorer/)                       │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 多阶段架构

#### 阶段1: 研究准备与多策略初始化

研究准备阶段实现自动化文献分析和想法生成：

**研究想法生成**: 系统使用专门的提示生成领域特定的研究想法：
```python
research_ideas = [
    "使用结合随机森林和XGBoost的集成方法",
    "应用多项式特征的高级特征工程",
    "使用SMOTE过采样处理类别不平衡",
    "实现交叉验证的堆叠",
    # ... 额外生成的想法
]
```

**多策略初始化**: 七种不同的初始化策略确保解决方案空间的全面覆盖：
1. **标准**: 使用scikit-learn的传统ML方法
2. **研究引导**: 整合生成的研究想法
3. **复制**: 基线方法重现
4. **逻辑回归复制**: 领域特定基线
5. **随机森林复制**: 基于树的基线
6. **目标改进**: 性能导向优化
7. **研究头脑风暴**: 多个想法的创意组合

#### 阶段2: 使用PUCT算法的增强树搜索

核心搜索阶段采用适应于代码生成的PUCT（多项式置信上界树）算法：

**选择策略**: 节点选择平衡探索和利用：
```
UCB(node) = Q(node) + c_puct * P(node) * sqrt(N_parent) / (1 + N(node))
```

其中：
- `Q(node)`: 平均性能分数
- `P(node)`: 来自LLM置信度的先验概率
- `c_puct`: 探索参数（默认：1.5）
- `N(node)`: 访问次数

**代码变异**: 基于以下因素的智能提示策略选择：
- 节点性能历史
- 生成数
- 先前变异成功率
- 研究想法适用性

#### 阶段3: 解决方案分析与混合化

最终阶段执行系统分析并创建混合解决方案：

**顶级解决方案分析**: 最佳候选的统计评估
**混合生成**: 成功方法的自动化组合
**性能验证**: 混合解决方案的全面测试

### 3.3 数据库驱动执行框架

#### 执行节点跟踪

每次代码生成尝试都作为执行节点存储，包含全面的元数据：

```python
class ExecutionNode:
    node_id: str                    # 唯一标识符
    parent_id: Optional[str]        # 树结构
    generation: int                 # 搜索深度
    mutation_type: str              # 使用的策略
    code: str                       # 生成的代码
    execution_status: ExecutionStatus  # completed/failed/pending
    score: Optional[float]          # 性能指标
    execution_duration: float       # 运行时间
    auto_fixes: int                 # trae-agent修正
    error_message: Optional[str]    # 失败详情
    created_at: datetime            # 时间戳
```

#### 安全代码执行

系统采用**trae-agent**进行安全的沙盒化代码执行，具有自动错误纠正功能：

1. **隔离**: 每个代码执行在独立环境中运行
2. **超时保护**: 300秒执行限制防止无限循环
3. **自动修复**: trae-agent为常见错误应用修正
4. **结果提取**: 性能指标的结构化输出解析

### 3.4 先进的提示工程

#### 代码截断问题的解决

**问题识别**: 初始测试显示代码在4,000个令牌处截断，尽管Gemini 2.5 Pro具有64,000令牌容量。

**解决方案实施**: 完全移除人工令牌限制：
```python
# 之前（有问题的）:
config=types.GenerateContentConfig(
    temperature=0.7,
    max_output_tokens=4000  # 人工限制
)

# 之后（修复的）:
config=types.GenerateContentConfig(
    temperature=0.7
    # 无令牌限制 - 使用完整模型容量
)
```

**影响**: 代码生成长度从约2,300增加到6,000+字符，实现完整函数实现。

#### 智能提示策略选择

系统采用基于以下因素的上下文感知提示选择：
- **性能历史**: 每种策略的先前成功率
- **生成上下文**: 父节点特征和搜索深度
- **研究整合**: 领域特定想法的适用性
- **多样性维护**: 确保探索广度

### 3.5 树搜索浏览器：可视化与分析

树搜索浏览器提供全面的可视化能力：

#### 交互式树可视化
- **D3.js驱动**的树渲染，具有平移/缩放功能
- **节点颜色编码**: 基于性能的可视化（红/黄/绿）
- **突破识别**: 重大改进的自动检测
- **点击探索**: 交互式节点选择和详情

#### 代码比较界面

- **并排差异视图**: 父-子代码比较
- **差异统计**: 添加/删除/修改行跟踪
- **搜索功能**: 大型代码库的快速导航

#### 性能分析
- **突破图**: 搜索迭代中的分数进展
- **策略效果**: 按变异类型的成功率

## 4. 实验设置

### 4.1 问题领域与数据集

**任务**: 工业设备机器故障的二元分类
**数据集**: Kaggle机器故障数据集
- **训练样本**: 8,000个实例
- **验证样本**: 2,000个实例
- **特征**: 空气温度、过程温度、转速、扭矩、工具磨损、机器类型
- **目标**: 二元故障预测（0/1）

**评估指标**: ROC曲线下面积（AUC）
**基线性能**: 该数据集的历史最佳性能范围0.85-0.95

### 4.2 系统配置

**LLM配置**:
- **模型**: 通过Vertex AI的Gemini 2.5 Pro
- **温度**: 0.7（变异），0.5（初始生成）
- **令牌限制**: 无（使用完整64K容量）
- **API**: 具有项目认证的Google Cloud Vertex AI

**搜索配置**:
- **算法**: c_puct = 1.5的PUCT
- **最大迭代**: 可变（测试5, 10, 20, 100）
- **超时**: 每次执行300秒
- **策略**: 7种初始化方法 + 4种变异类型

**基础设施**:
- **计算**: 标准CPU节点（无需GPU）
- **存储**: 用于执行跟踪的SQLite数据库
- **环境**: Python 3.11，包含scikit-learn、XGBoost、LightGBM
- **隔离**: trae-agent沙盒执行

### 4.3 实验设计

#### 实验1: 令牌限制影响分析
**目标**: 量化移除令牌限制对代码完整性的影响
**设置**: 比较移除令牌限制前后的代码生成
**指标**: 代码长度、函数完整性、执行成功率

#### 实验2: 多阶段性能评估
**目标**: 评估多阶段架构的有效性
**设置**: 比较单阶段与多阶段执行
**指标**: 达到的最佳分数、收敛时间、解决方案多样性

#### 实验3: 策略有效性分析
**目标**: 评估不同初始化策略的性能
**设置**: 按策略跟踪成功率和分数分布
**指标**: AUC分数、成功率、策略特定性能

#### 实验4: 可扩展性与收敛测试
**目标**: 评估系统在不同迭代数下的性能
**设置**: 运行5、10、20和100次迭代的实验
**指标**: 达到的最佳分数、收敛模式、递减收益
