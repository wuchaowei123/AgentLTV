### **Subject:** Implementation Plan for "Tree Search Explorer" UI

Hi team,

We're building a new user interface to visualize the results of our AI-driven code generation system. This "Tree Search Explorer" will allow researchers to inspect the entire search process, understand key breakthroughs, and compare different code solutions.

Please use the provided screenshot as your design reference. The page consists of four main components. Here's a detailed breakdown of what needs to be built.

#### **1. Data Requirements**

First, you'll need to work with the data generated by the backend search process. For each "search run" (e.g., "172492931-COVID Forecasting"), you will receive a dataset (likely a large JSON file or a set of related files) containing the following information for **every node** in the search tree:

*   `node_id`: A unique identifier (e.g., `1937`).
*   `parent_id`: The ID of the node it was generated from.
*   `score`: The numerical score of this node (e.g., `-40.5330`).
*   `status`: The execution result (e.g., `Success`, `Error`).
*   `code`: The full Python code string for this node.
*   `llm_summary`: An LLM-generated summary of what the code does.
*   `code_diff_summary`: An LLM-generated summary of the differences between this node's code and its parent's code.

---

### **2. Page Components & Implementation Details**

The page is divided into four main sections.

#### **Component 1: Header**

*   **Content:**
    *   A main title that displays the Search Run ID, e.g., **"172492931-COVID Forecasting"**.
*   **Implementation:**
    *   This should be a simple `<h1>` or `<h2>` tag. The ID should be dynamically loaded based on the search run being viewed.

#### **Component 2: Top-Level Summary & Visualizations (Two-Column Layout)**

This section provides a high-level overview of the entire search process. It should be a two-column layout.

**Left Column: "Breakthrough Plot"**

*   **Functionality:** A line chart that visualizes the improvement of the **best score found so far** over the course of the search.
*   **Implementation:**
    *   **X-axis:** "# nodes" (from 1 to the total number of nodes generated).
    *   **Y-axis:** "maximum score".
    *   **Data Processing:** Before rendering, you must process the node data. Create an array where the value at index `i` is the best score found among the first `i` nodes.
    *   **Line:** Plot this "best score over time" array as a solid blue line.
    *   **Breakthrough Points:** Identify the nodes where the best score improved (i.e., where the line chart jumps up). Mark these points on the line chart with prominent green circles.
    *   **Interactivity (Crucial):** When a user **hovers over or clicks a green circle (a breakthrough point)**, the entire page should update to display the details of that specific breakthrough node. This includes updating the "Node Details" panel, the "Tree Visualization," and the "Code Diff" panel.

**Right Column: "Node Details" Panel**

*   **Functionality:** Displays detailed information about the currently selected node. By default, it should show the **best node found in the entire search**.
*   **Implementation:**
    *   **Title:** "Node #[node_id]" (e.g., **"Node #1937"**).
    *   **Status & Score:** Display the `status` and `score` of the selected node.
    *   **LLM Summary:** Render the `llm_summary` text under a heading like **"LLM summary of solution [node_id]"**. This should be a bulleted list.
    *   **Differences Summary:** Render the `code_diff_summary` text under a heading like **"Differences from the parent solution"**. This should also be a bulleted list. If the selected node is the root node (no parent), this section should be hidden.

#### **Component 3: Tree Visualization**

*   **Functionality:** An interactive, top-down visualization of the entire search tree.
*   **Implementation:**
    *   Use a tree/graph visualization library like **D3.js**, **vis.js**, or a React-specific library if applicable (e.g., React Flow). D3's tree layout is ideal for this.
    *   **Nodes:** Each node in the visualization should represent a node from our dataset. The root node (`parent_id` is null) should be at the top.
    *   **Edges:** Draw lines connecting each node to its parent.
    *   **Node Coloring:**
        *   **Default (Purple):** Regular nodes.
        *   **Breakthrough (Teal/Green):** Nodes that represent a new best score.
        *   **Selected (Highlighted):** The currently selected node (and its parent, if applicable) should have a distinct highlight (e.g., a thicker border or different color) to show the user what they are viewing.
    *   **Interactivity:**
        *   **Clicking a node** in the tree should update the entire page to reflect that node's details (updating the Node Details panel and the Code Diff panel).
        *   The tree should support **panning and zooming** as the trees can become very large and wide. Add UI controls (like the arrow button in the screenshot) or enable mouse/trackpad gestures for navigation.

#### **Component 4: Code Comparison Panel ("Code Diff")**

*   **Functionality:** A side-by-side view that compares the code of the currently selected node ("Child") with the code of its parent node ("Parent").
*   **Implementation:**
    *   Use a two-column layout. The left column is for the parent, the right for the child.
    *   **Headers:** Display "Parent #[parent_id]" and "Child #[child_id]".
    *   **Code Display:**
        *   Use a proper code viewer component (like Monaco Editor, CodeMirror, or Prism.js) to display the code with syntax highlighting for Python. This is much better than a plain `<pre>` tag.
        *   Load the `code` string for the selected node and its parent into these viewers.
    *   **Diff Highlighting (Advanced but highly recommended):** To make the changes obvious, use a diffing library (e.g., `diff-match-patch` or a library integrated with your code viewer) to highlight the lines that were added, removed, or changed between the parent and child code. This is the most valuable feature of this component.
    *   **State Handling:** If the selected node is the root node, the "Parent" column should be empty or display a message like "This is the root node."

### **Summary of User Interaction Flow**

1.  **Page Load:** The page loads and displays the details for the **overall best node** found in the search. The breakthrough plot is fully rendered, and the tree is drawn. The best node is highlighted in the tree.
2.  **User Clicks a Breakthrough Point:** The user clicks a green circle on the line chart. The page updates to show the details of that specific breakthrough node.
3.  **User Clicks a Node in the Tree:** The user clicks any node in the tree visualization. The page updates to show the details of that node, including its parent-child code comparison.
